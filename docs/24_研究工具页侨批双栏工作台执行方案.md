# 研究工具页：侨批双栏工作台执行方案

日期：2026-10-08。状态：用户已要求执行；双栏页面、草稿导出、服务适配层与服务端代码已实现，通过本地验证；真实供应商和常驻HTTPS后端尚待确认，尚未验证真实模型识读质量。依据用户本次要求：在工具页增加侨批工作台，左边上传图片，右边识别转译。执行与上线结果见 `25_侨批工作台实施与验收记录.md`。

## 1. 产品目标与入口

在 `research.html` 增加“研究分析 / 侨批工作台”两个页内标签。默认保留现有研究分析；选择“侨批工作台”后，主内容区显示完整双栏工作区，不用弹窗承载长时间识别任务。

- 研究工具页的快捷工具区增加“侨批工作台”卡片，点击切换至工作台。
- 工作台状态可直达：`research.html?tool=qiaopi`。
- 保留已有 `qiaopi-workbench.html` 入口，它与工具页复用同一组件；从侨批详情进入时传入 `id`，加载对应侨批，而不是总取第一条。
- 已有 `qiaopi-workbench.html?id=...` 链接继续可用；加载不到指定记录时明确提示，不显示其他侨批冒充。
- 本方案将“转译”默认定义为现代汉语白话释读。保留原文转写，第一版不扩展外语翻译、关系抽取或自动入库。

## 2. 双栏布局

沿用侨脉纸张底色、棕金按钮、宋体标题、细边框及本地 Lucide 图标。最大内容宽度 1536px。去掉旧工作台左侧步骤导航和第三栏结构化字段，避免挤压原件与结果。

```text
研究工具                  [研究分析] [侨批工作台]
侨批工作台                   [开始识别并转译]
┌────────────────────────┬────────────────────────┐
│ 原始图片               │ 识别原文               │
│ [上传图片] [更换图片]   │ 状态：等待 / 识别中    │
│                        │                        │
│                        │ 可编辑的逐行转写文本   │
│    完整原图预览        │ [复制原文] [重新识别]  │
│                        ├────────────────────────┤
│                        │ 白话转译               │
│                        │                        │
│                        │ 与原文对应的现代释读   │
│ [−] [适应窗口] [+] [↻] │ [复制转译] [重新转译]  │
├────────────────────────┴────────────────────────┤
│ 文件名、页码                  [下载结果] [清空] │
└─────────────────────────────────────────────────┘
```

| 区域 | 桌面设计 | 主要内容 |
|---|---|---|
| 左栏 | 约52%，优先保证原件可读 | 上传区、原图、缩放、适应窗口、旋转查看 |
| 右栏 | 约48%，上下两块 | 上：识别原文；下：现代汉语转译 |
| 栏间 | 20–24px | 固定清晰间隔，第一版不增加可拖拽分栏 |
| 工作区 | 按视口计算高度，桌面建议560–720px | 两栏并排；原图和长文本各在栏内浏览 |

右侧同时可见原文和转译，不用只显示一项的标签切换。文字默认16px、行高1.7–1.9；正文区域最小高度约220px。窄屏不强行维持两栏。

### 手机与平板

- 宽度≥1024px：双栏并排。
- 宽度<1024px：原图在上、识别原文和转译在下；图片默认适应宽度，支持全屏查看。
- 手机文本随页面自然滚动，不叠加多个固定高度的小滚动框。
- 主操作按钮始终可到达，上传后立即看到文件预览；无整页横向溢出。

## 3. 左栏：上传和原图

第一版支持单张 JPG/JPEG、PNG、WebP。支持点击选择、拖放；单图建议上限20MB，同时限制解码后的像素数量。上传前检查格式、大小和实际是否可解码，不能只看扩展名。PDF、HEIC和批量档案作为后续扩展，不纳入第一版验收。

1. 初始状态为拖放框：“上传侨批图片”，不预置其他侨批作为用户原件。
2. 选择后先在浏览器本地预览，显示文件名、尺寸；只有点击“开始识别并转译”才将文件提交到识别服务。
3. 图片使用 `object-fit:contain`，打开、更换及窗口变化后自动适应居中，保留整张图及原色，不裁掉批文、邮戳或印章。
4. 缩放和90°旋转仅改变查看姿态，不覆盖原始文件，不做去水印、修补或重绘。识别所需方向参数单独传递。
5. 更换图片时取消前一任务，并立即清空其原文、转译及导出状态；旧任务晚返回也不能覆盖新图。
6. 从资料库打开时，只读取本件已有原件；没有原件就显示上传入口，不拿其他侨批图片替代。

用户临时上传用于个人识读，与公开资料库原件分开存储；识读结果和上传图片均不自动公开或自动进入已有侨批记录。

## 4. 右栏：识别原文与白话转译

### 识别原文

- 支持侨批常见竖排、繁体、异体字和混合排版；按实际阅读顺序输出逐行文本。
- 优先忠实保留姓名、称谓、原地名、日期、币种和金额。缺字用 `□` 表示，不根据上下文补造姓名、金额或日期。
- 机器原始识别结果单独保留；可编辑区域保存人工校订版本。符合 docs/09 中 raw_ocr、diplomatic_transcription、normalized_text 的区分。
- 不明确的字句可附简短释读备注；只有服务提供可靠定位或置信信息时才显示高亮和置信值，不编造百分比。
- 原文编辑后标记“原文已更新”，提示重新转译；原始机器结果可恢复，不被编辑覆盖。

### 白话转译

- 根据当前校订原文生成通顺的现代汉语释读，按原文段落对应输出。
- 默认保留历史人名、地名和金额原称；解释放在独立注释中，不直接替换成未经确认的实体或现代货币数值。
- 看不清的内容对应说明，不把 `□` 自动补成一个确定事实。字段缺失使用“不详”，图像文字不可辨识使用缺字标记。
- 转译结果可编辑、复制；重新转译前保留用户手动修改版本，避免无提示覆盖。
- 第一版只做原文与白话转译，不自动建立人物、家族、汇款或迁徙关系。

原文与转译分开展示和导出，避免把现代释读当成历史原文引用。

## 5. 操作流程和状态

基本流程：上传图片 → 本地预览 → 点击“开始识别并转译” → 识别原文 → 自动生成白话转译 → 校订、复制或下载。

| 状态 | 左栏 | 右栏与操作 |
|---|---|---|
| 未上传 | 上传框 | 简短引导，识别按钮不可用 |
| 已上传 | 完整预览 | 原文/转译为空，可开始 |
| 识别中 | 保留原图 | 显示实际任务阶段，可取消，不编造进度百分比 |
| 转译中 | 保留原图 | 已完成的原文立即可读；转译区显示进行中 |
| 已完成 | 保留原图 | 两块结果可编辑、复制、下载 |
| 识别失败 | 保留原图 | 说明本次失败，可重试；不填入固定示例文本 |
| 转译失败 | 保留原图 | 保留成功原文，只重试转译 |
| 更换/清空 | 新图或上传框 | 取消旧任务，清空旧结果，防止图文错配 |

其他规则：

- 原文无有效文字时不启动转译，提示换更清晰的图片或手动输入。
- “重新转译”只提交当前原文，不重复上传图片或重复做识别。
- 下载第一版支持 TXT 和 JSON：包含文件名、原始识别、校订原文、白话转译和生成时间；不导出身份凭据或临时访问令牌。
- 本地草稿按明确的“保存草稿”操作保存；刷新可恢复已保存草稿。未保存内容离开页面前提示，避免上传后无意丢失。
- 从资料库打开的记录仍按其稳定 ID 加载，修改只保存在本次草稿；本轮不增加“自动发布”按钮。

## 6. 现有实现偏差和替换方式

当前 `research.js` 的快捷分析只有人物对比、迁徙路径、侨批分布、组织网络，没有工作台入口。

现有 `qiaopi-workbench.html` 使用 `legacy-app.js / legacy-styles.css`，是“侧边导航＋三块内容”的旧布局。`renderWorkbench()` 有以下需替换的逻辑：

- 固定取侨批第一条，忽略 URL 的 `id`。
- 上传只替换图片预览；识别按钮始终返回固定示例文案。
- 结构化字段来自第一条侨批，与用户图片无关。
- 没有白话转译、真实任务状态和可靠的保存过程。

实施时迁出独立双栏组件，切断工作台对旧渲染器的依赖；其他仍使用旧代码的地方暂不连带重构。

## 8. 真实识别和转译的接入边界

这是内部技术实施约束，不在产品主界面放长篇技术说明。

目前正式站点部署在 GitHub Pages。页面可以完成上传控件、本地预览、文本编辑和本地导出；真实识别与转译还需要独立运行的 HTTPS 服务端接口。不能把 Codex 聊天中的原生读图能力当作网页可直接调用的公共接口，也不能只改按钮名称就声称完成识别。

建议由统一服务适配器实现以下接口，名称为项目设计，并非现有接口：

| 方法与路径 | 用途 |
|---|---|
| `POST /api/v1/qiaopi/recognition-jobs` | 提交本次图片及查看方向，返回任务 ID |
| `GET /api/v1/qiaopi/recognition-jobs/{jobId}` | 获取任务阶段、原文和识别备注 |
| `POST /api/v1/qiaopi/translation-jobs` | 提交当前校订原文，生成白话转译 |
| `GET /api/v1/qiaopi/translation-jobs/{jobId}` | 获取转译阶段及结果 |
| `POST /api/v1/qiaopi/jobs/{jobId}/cancel` | 取消服务端任务；前端同时忽略过期响应 |

原文与转译任务分开，便于转译失败后单独重试。每个任务携带本次图片标识；转译结果携带原文版本，防止原文已修改却显示旧转译。

- 服务端保存供应商密钥，仅从环境变量读取；不写入 HTML、JavaScript、GitHub 仓库或浏览器存储。
- 静态站点通过可配置的 API 地址访问，CORS 允许正式站点域名；接入侧设置文件大小、像素数、频率、超时和任务有效期。
- API 不接受任意远程 URL 代抓图片。临时图片和任务只对本次访问会话开放，不提供公开遍历列表；按明确有效期清理。
- 实施前需确定识别/转译服务、后端运行位置及计费上限。本轮只规划，不新开付费服务、不调用外部视觉供应商。
- 测试替身仅在开发环境使用；上线识别验收必须使用真实图片返回的实际结果，不用固定示例冒充。

## 9. 分阶段执行与验收

1. **布局与入口**：工具页可切换，独立路由正常；桌面双栏、手机纵排，保持已有研究功能。
2. **上传与查看**：校验真实图片、完整居中预览、缩放旋转、清空与更换，保存本地草稿。
3. **任务接口**：接入真实识别和转译，补齐取消、重试、超时和图文版本防串任务。
4. **校订与输出**：原文编辑后重译、保留版本、复制和TXT/JSON导出。
5. **上线验证**：发布到现有侨脉.wiki；直接深链接刷新可用，匿名访问、图片上传及两阶段服务请求通过。

验收重点：

- 1440/1024px 双栏，390/414px 纵向；没有第三栏、步骤侧边栏或整页横向溢出。
- 用两张内容不同的侨批分别识别，结果确实对应各自图片；不能返回同一固定文本。
- 竖排原件不裁字，姓名、金额、日期逐项对照原图；不确定内容保留缺字和说明。
- 原文、人工校订、白话转译分开保存；修改原文后可独立重新转译。
- A图任务运行中换B图，A结果晚返回不能出现到B图旁；取消、空结果和服务失败都保持当前图文关系正确。
- 从不同侨批详情进入，加载对应ID；无原件、无效ID和格式错误分别处理。
- 服务未完成时不显示成功，不产生假下载或假入库提示；真实服务接通后才能把识别阶段标为完成。
- 页面没有密钥，临时识读文件不因操作而自动成为公开资料。
