# 侨脉资料采集与内容填充总则

适用项目：D:\APP\侨脉  
适用页面：首页、人物、家族、地点、事件、组织、历史档案、侨批、研究工具。  
目的：把“网上搜到一些资料”变成可直接写入侨脉数据库和前端页面的标准化数据包。

# 1. 核心原则

侨脉的资料采集不是写百科文章，而是为九个页面准备可关联的数据。每个采集任务最终都必须回答五件事：

1. 这个对象是谁/是什么。
2. 它发生在什么时间和地点。
3. 它与哪些人物、家族、组织、事件、档案、侨批有关。
4. 哪一条资料支持哪一个事实。
5. 前端需要哪一张图片、哪一段短文本和哪些结构化字段。

任何资料不得只交一段长文章。最终必须拆成字段、关系和来源。

# 2. 推荐数据来源层级

A 级：官方/原始资料
- 档案馆、博物馆、大学、政府、联合国教科文组织。
- 原始侨批、族谱、名册、移民记录、报刊原件、机构档案。
- 官方人物/组织页面。

B 级：可信研究资料
- 学术论文。
- 学术专著。
- 大学数字人文项目。
- 经过编目的专业数据库。

C 级：开放知识库
- Wikidata。
- Wikipedia。
- Wikimedia Commons。
- 其他可明确识别来源和许可的知识平台。

D 级：线索来源
- 百度百科。
- 新闻转载。
- 博客、自媒体。
- 未注明来源的网页。

D 级可以帮助发现名字、别名、年份、地点和关键词，但核心事实应尽量回到 A/B/C 级来源确认。非商用不等于可随意批量复制受版权保护正文或图片。

# 3. 每条事实最少保存什么

每个事实记录至少保留：

| 字段 | 含义 |
|---|---|
| fact_id | 本地事实 ID |
| subject_id | 主体，如人物/组织/地点 |
| predicate | 关系或属性，如“出生于”“创办”“迁居” |
| object_value / object_id | 值或关联实体 |
| date_raw | 原文日期 |
| date_normalized | 标准化日期 |
| source_name | 来源名称 |
| source_url | 来源链接 |
| source_title | 来源页面/文献标题 |
| source_quote | 支持该事实的短摘录或原文定位 |
| page_or_locator | 页码、档号、段落、图片坐标等 |
| review_status | candidate / reviewed / disputed |
| note | 冲突、疑点、换算说明 |

一个来源中出现的 10 个事实，应拆成 10 条事实，但可共用 source_id。

# 4. 每个对象最少保存什么

所有对象统一保存：

- stable_id
- object_type
- canonical_name
- aliases
- short_summary
- time_range
- region_tags
- source_ids
- image_ids
- relation_ids
- review_status

禁止使用“姓名字符串”代替对象 ID 关联。

# 5. 图片采集统一格式

每张图片必须同时记录：

- image_id
- object_id
- image_type
- title
- source_url
- source_name
- author / photographer（可得时）
- date（可得时）
- license / rights_note
- original_width
- original_height
- local_filename
- crop_recommendation
- caption
- review_status

推荐文件名：

person_陈嘉庚_portrait_01.jpg  
place_新加坡_harbour_1930_01.jpg  
org_厦门大学_building_01.jpg  
doc_QP001_front.jpg

禁止：
- 从搜索结果页直接截缩略图当正式素材。
- 不记录来源的图片。
- 用 AI 生成历史人物肖像冒充真实照片。
- 将带巨大平台水印的图片作为主视觉。

# 6. 文本长度标准

| 内容 | 建议长度 |
|---|---:|
| 一句话摘要 | 35–60 字 |
| 主档简介 | 80–150 字 |
| 卡片摘要 | 25–55 字 |
| 事件说明 | 30–80 字 |
| 地点说明 | 50–120 字 |
| 组织简介 | 80–150 字 |
| 档案简介 | 60–120 字 |
| 首页推荐理由 | 20–40 字 |

不要直接把百科 500–1000 字复制进页面。

# 7. 日期标准

同时保存：
- date_raw：如“民国二十一年五月十二日”。
- date_normalized：如“1932-05-12”。
- date_precision：day / month / year / range / unknown。
- calendar_note：换算依据。

无法精确时：
- 1930年代 → 1930-01-01 ~ 1939-12-31，precision=decade。
- 约1920年 → date_label=约1920年，不伪装成精确日期。

# 8. 地点标准

同时保存：
- original_place_name
- canonical_place_id
- canonical_name
- historical_alias
- modern_parent
- country
- coordinates（有可信来源时）
- spatial_precision

例如原文“星洲”：
- original_place_name=星洲
- canonical_name=新加坡
- alias_type=historical/common
- 原文仍显示“星洲”。

# 9. 搜索方法

任何对象建议至少执行四组搜索：

第一组：对象本体
- “对象名”
- “对象名 生平 / 历史 / 简介”
- “对象名 档案”
- “对象名 site:gov.cn / edu.cn / archive”

第二组：关系
- “对象名 家族 / 父亲 / 母亲 / 配偶 / 子女”
- “对象名 创办 / 任职 / 加入 / 会馆 / 商会”
- “对象名 新加坡 / 马来西亚 / 美国 / 南洋”
- “对象名 侨批 / 书信 / 汇款”

第三组：图片
- “对象名 历史照片”
- “对象名 old photo”
- “对象名 Wikimedia Commons”
- “对象名 档案馆 图片”

第四组：交叉验证
- 中文名 + 英文名。
- 中文名 + 出生地。
- 中文名 + 年份。
- 英文音译 + 籍贯。

# 10. 百度百科使用方式

百度百科可以用于快速发现：
- 生卒年。
- 别名。
- 籍贯。
- 组织名。
- 家族成员名字。
- 重大事件关键词。
- 图片线索。

但采集任务不能只提交“百度百科说”。标准流程是：

百度百科发现线索
→ 记录关键词
→ 搜官方/学术/Wikipedia/Wikidata/原始档案
→ 找到更直接来源
→ 把事实写入结构化字段
→ 百度百科可作为辅助 source，不作为唯一强证据。

若某一事实只有百度百科能找到：
- 可以标 candidate。
- 页面可暂时使用，但 review_status 必须标“待复核”。
- 不用于家族关系、具体金额、精确日期等高风险断言的最终确认。

# 11. 内容冲突

不同来源冲突时不自行“选一个看起来对的”。

记录：
- claim A
- source A
- claim B
- source B
- conflict_note
- review_status=disputed

页面可显示“资料记载不一”。

# 12. 一个采集任务的标准交付包

以“陈嘉庚”为例，一个人完成后至少交付：

- person.json / person.xlsx 一行主档。
- aliases.csv。
- events.csv。
- relations.csv。
- family_relations.csv。
- places.csv。
- organizations.csv。
- documents.csv。
- images.csv。
- sources.csv。
- 1 个 Markdown 采集报告，写明缺口和争议。

前端不直接读取采集报告，而读取结构化数据。

# 13. 完成度等级

Complete：
- 主档必填字段 90% 以上。
- 至少 3 个可靠来源。
- 至少 1 张可合法展示图片或明确无图。
- 至少 3 个关联对象。
- 关键事实有证据。

Usable：
- 主档能展示。
- 至少 2 来源。
- 关系较少。
- 可进入前台但标记资料不完整。

Candidate：
- 只有初步线索。
- 尚未完成交叉验证。
- 不进入正式统计或只在内部显示。

# 14. 总体验收

- [ ] 没有只交百科长文而不拆字段。
- [ ] 每个事实能追溯来源。
- [ ] 图片有来源和权限说明。
- [ ] 人物、地点、组织、事件都有稳定 ID。
- [ ] 页面关系不是靠字符串临时匹配。
- [ ] 未确认内容标 candidate。
- [ ] 百度等线索来源不被误写成唯一权威证据。
- [ ] 搜索到的信息最终能对应到九页中的具体模块。
