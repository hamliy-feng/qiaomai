# 侨脉全量真实图片采集、尺寸适配与前端填充执行方案

日期：2026-10-08  
适用项目：D:\APP\侨脉  
目标：解决当前全量资料已经入库但绝大多数实体没有真实图片的问题。所有图片必须来自真实公开/授权资料源，不生成、不仿制、不使用 AI 补图。图片下载到本地，建立来源与许可元数据，生成适合 Web 的派生尺寸，再由统一构建脚本写入前端数据。

# 1. 总目标

当前演示数据库已有：

- 人物 1001
- 家族 89
- 地点 383
- 组织 126
- 事件 2774
- 历史档案 1208
- 侨批 81

图像工程目标不是为 4462 条记录各找一张互不相同的图片，而是先把“实体主图资产”做完整，再由事件和档案继承真实关联对象的图片。

需要独立对外搜索的主任务：

| 类型 | 数量 | 主图目标 |
|---|---:|---|
| 人物 | 1001 | 肖像 / 可确认人物的合影 / 人物档案影像 |
| 组织 | 126 | 历史建筑 / 现址 / 组织历史照片 |
| 地点 | 383 | 历史城市、港口、街区、建筑或代表景观 |
| 家族 | 89 | 家族合影 / 祖屋 / 宗祠 / 族谱封面 |
| 侨批 | 81 | 本件真实原件页 |
| 外部主图采集任务合计 | 1680 | 不含复用型事件/档案 |

事件和档案不强求独立新图：
- 事件 2774：现场照 > 同期人物 > 相关组织 > 相关地点 > 证据档案。
- 人物资料档案：复用该人物真实肖像。
- 组织资料档案：复用该组织真实主图。
- 侨批档案：只使用该件侨批自己的真实原件。

# 2. 硬规则

1. 不使用 AI 生成历史人物、历史场景、建筑、侨批、档案原件。
2. 不使用 AI inpainting、生成式扩图、换脸、重绘、伪老照片。
3. 不通过裁切、涂抹、模糊或修复去除水印。
4. 人物肖像必须能确认是本人；同名人物不能靠文件名猜。
5. 事件图片不能拿几十年后的现代照片冒充事件现场。
6. 档案和侨批 Viewer 只能展示本件原件，不用“相似档案”顶替。
7. 允许的技术处理只有：
   - 原尺寸保存。
   - 方向校正。
   - WebP/JPEG 派生。
   - 非档案类图片的常规构图裁切。
   - 缩放。
   - CSS 灰度/sepia/亮度处理。
8. 原文件必须保留，不覆盖。
9. 所有图片必须写 source_url、author、license/rights_basis、caption、local_path、sha256。
10. 前端不直接依赖远程图片，最终演示使用本地派生文件。

# 3. 图片来源优先级

人物、组织、地点首先走结构化来源，不先进行无差别网页搜图。

第一优先：
- Wikidata P18。
- Wikimedia Commons。
- Wikipedia 主图，但必须回溯到 Commons/File 页面取得作者和许可。

第二优先：
- 新加坡国家图书馆 NLB / BiblioAsia / 数字馆藏。
- 新加坡国家档案馆、National Heritage Board / Roots。
- 大学档案馆、大学纪念馆、校史馆。
- Library of Congress、国家/地方档案馆、博物馆数字馆藏。
- 广东、福建及侨务机构的官方资料。
- 组织官方网站的历史图库；只有许可或授权依据清楚时才本地下载。

第三优先：
- 百度、Google/Bing 搜图只作为“发现入口”。
- 找到图片后必须回溯到原始机构、Commons、档案馆、大学或原出版来源。
- 不把百度图片缓存、内容农场、转载博客当最终 source_url。

# 4. 人物 1001 张主图

每个人物的搜索顺序固定：

1. QID → Wikidata P18。
2. P18 文件 → Commons imageinfo → 原图、尺寸、作者、许可。
3. 中文名 / 繁体名 / 英文名 → Commons 搜索。
4. Wikipedia 页面主图 → 回溯 Commons。
5. 大学、科学院、博物馆、档案馆、纪念馆、官方传记。
6. 报刊/历史数据库中明确标注人物身份的照片。

人物图的可接受层级：

A：
- 标准单人肖像。

B：
- 明确标出人物的半身/全身历史照。

C：
- 确认人物位于其中的合影。

D：
- 如果确实没有人像，使用与本人直接相关的真实签名、墓碑、手稿、护照/档案照片等作为“人物档案影像”，但不能标成肖像。

主肖像标准：
- 目标比例 4:5。
- 原图尽量 >= 800×1000。
- 最低不得低于短边 500px，除非历史人物只有小尺寸原件。
- 人脸清晰，不把严重马赛克或网页截图作为主图。
- 原始宽高不够时不 AI 放大伪造细节。

派生：
- portrait-800x1000.webp：人物详情/列表。
- portrait-320x400.webp：卡片缩略。
- 原图独立保存。

已有 R02 人物 image_candidate 和 Wikidata QID 应优先利用，不从零开始。

# 5. 组织 126 张主图

每个组织至少绑定一张 hero。

优先：
1. 历史会馆/校舍/商号/办公建筑。
2. 有年代说明的组织历史照片。
3. 组织现址建筑，caption 明确写“现址/今貌”。
4. 组织官方馆藏历史图片。
5. 无建筑资料时，可使用该组织正式标识或档案，但不能把 Logo 伪装成建筑历史照。

尺寸：
- 原图至少 1200px 宽优先。
- hero-1440x810.webp，16:9。
- card-800x600.webp，4:3。
- thumb-320x240.webp。

前端：
- 组织主卡使用 hero。
- 列表使用 thumb。
- 组织资料档案默认继承组织 hero。

# 6. 地点 383 张主图

地点优先找：
1. 历史城市/港口/街区全景。
2. 华人街、码头、会馆群、侨乡建筑。
3. 历史地图。
4. 代表性建筑。
5. 现代图只有在没有合适历史图时使用，并写清“今貌”。

尺寸：
- hero：1440×810。
- card：800×600。
- thumb：320×240。

地点主图必须与 canonical place 对应。
县、市、村不能混用一张不注明位置的泛景图。

# 7. 家族 89 张主图

家族图不要求一定是“全家福”，但必须是真实关联资料。

优先：
1. 家族合影。
2. 祖屋。
3. 宗祠。
4. 族谱封面。
5. 多位核心成员合照。
6. 找不到家族独有图时，可复用已经确认的祖籍地建筑/核心人物历史合影，并在 caption 写清图片角色。

尺寸：
- 16:9 或 3:2。
- hero 1440×810 或 1440×960。
- thumb 320×240。

家族世系图中的人物头像直接复用 Person 图片，不重复下载。

# 8. 事件 2774 条如何做到“都有图”

不为所有事件单独搜索一张新图片。

自动媒体解析顺序：

1. event.media：存在事件现场图则直接用。
2. 关联 document 的本件历史图。
3. 关联 person 的主肖像。
4. 关联 organization 的主图。
5. 关联 place 的主图。
6. 都没有才显示统一空图。

只有 importance 高、首页/事件详情重点展示的事件，再单独检索事件现场。

这样每条事件都可以有视觉内容，同时不会把不相干历史照片当事件现场。

事件图片字段必须记录：
- media_basis=event_scene / document / person / organization / place
- media_entity_id
- caption

# 9. 历史档案 1208 条

现在 1208 条中大量是“人物资料档案”和“组织资料档案”，不应假装它们都有历史扫描件。

规则：

人物资料档案：
- cover_image = 对应 Person 主图。

组织资料档案：
- cover_image = 对应 Organization hero。

真实历史档案：
- cover_image = 本件第一页/封面。
- Viewer = 本件所有原页。

不得将人物肖像放进 Viewer 冒充原档案；人物图只作为列表 cover。

原件 Viewer：
- 原图优先。
- 单边 >= 1600px 更好。
- object-fit: contain。
- 不裁边缘、印章、邮票和页码。

# 10. 侨批 81 件

侨批与其他对象不同，必须逐件匹配。

每件需要：
- 批封/信封。
- 内信正面。
- 内信背面。
- 汇款凭证。
- 附条。
- 如果来源有多页，全部按顺序保存。

硬条件：
- 必须是该 archive_number 对应的本件原件。
- 不用其他侨批作为替代。
- 不用生成图。
- 不去水印。
- 不裁切逃避水印。
- Viewer 必须是完整页。

如果目前广东省档案馆只提供带水印预览：
- 继续追原馆数字档案下载接口、开放高清页或授权版本。
- 找不到 clean_original 时，Viewer 保持无原件，不以无关图片顶替。
- 列表可显示“档案记录”文本卡；不能用其他侨批做缩略图。

这 81 件是整个图片工程唯一不能靠关联实体复用解决的部分。

# 13. 前端数据接法

实体统一增加：

```json
"media": {
  "url": "assets/media/entities/person/person_wd_Qxxxx/portrait-800x1000.webp",
  "caption": "...",
  "sourceUrl": "...",
  "author": "...",
  "license": "...",
  "licenseUrl": "..."
}
```

多图：

```json
"mediaGallery": []
```

档案/侨批继续使用：

```json
"pages": []
```

现有 core.media() 已经支持实体 `media.url`，所以主要工作是让构建脚本读取 media_manifest，并把 primary 图片挂到对应 Entity。

事件构建时执行媒体继承，不额外人工写 2774 份图片映射。

# 14. 图片尺寸与包体

人物：
- 800×1000，WebP q≈82。
- 320×400 缩略。
- 目标 80–300KB/派生图。

组织/地点/家族：
- 1440×810 hero。
- 800×600 card。
- 320×240 thumb。
- hero 目标 180–450KB。

档案/侨批：
- 原件不为减包体牺牲可读性。
- Viewer 使用原件或高分辨率派生。
- 列表 thumb 320–480px。
- 原文件放 data/media_original，不跟网页演示包重复携带全部超大原件。

前端展示包预计以 200–400MB 为合理上限；原始高清史料另存，不强行压入网页包。

# 15. 搜索 Agent 执行方式

不直接 1000 并发请求。

建议：
- 4–6 个并发 worker。
- Wikimedia/Wikidata 请求间隔 0.8–1.5 秒。
- 遇到 429 使用指数退避。
- 每完成 25–50 个实体写 checkpoint。
- 每条实体最多先保留 3 个候选来源，选主图后再下载。

人物搜索 query 自动生成：
- 中文标准名 + Wikimedia Commons
- 繁体名 + Wikimedia Commons
- 英文名 + Wikimedia Commons
- 中文名 + 历史照片
- 中文名 + 档案馆/大学/纪念馆

组织：
- 名称 + old photo
- 名称 + 历史建筑
- 英文名 + Wikimedia Commons

地点：
- 地点 + old photo
- 地点 + port / Chinatown / historic
- 地点 + Wikimedia Commons

家族：
- 核心人物 + family
- 姓氏 + 祖屋/宗祠/族谱 + 地点

# 16. 图片选择规则

同一实体候选图排序：

1. 身份完全匹配。
2. 来源专业。
3. 授权明确。
4. 原图尺寸高。
5. 历史年代更贴合。
6. 构图符合当前页面。
7. 无明显机构水印/宣传字覆盖。
8. 无人工编辑痕迹。

不以“看起来漂亮”为第一排序。

# 17. 去重

使用：
- source URL 去重。
- SHA-256 去重。
- 可选 perceptual hash 做近重复识别。

同一张真实图允许：
- 人物页主图。
- 家族成员头像。
- 事件关联图。
- 人物档案 cover。

不为“看起来丰富”复制下载成四个不同文件。

# 18. 首页图片

首页不随机取图，固定策展。

需要：
- 3–6 位高质量人物肖像。
- 1 张广东/福建侨乡历史图。
- 1 张新加坡/南洋港口历史图。
- 1–2 张许可清楚的侨批原件。
- 组织建筑 1–2 张。

七类入口卡直接从已有实体 media 中选 featured，不额外造图。

# 20. 实际施工入口

建议新增并固定以下脚本：

- scripts/build_media_acquisition_queue.mjs

- scripts/download_entity_media.mjs
- scripts/build_media_derivatives.mjs

最终数据流：

Entity 数据  
→ IMAGE_QUEUE  
→ Wikidata/Commons/专业馆藏搜索  
→ 下载原图  
→ media_manifest  
→ 生成 Web 派生图  
→ attach_media_to_frontend  
→ frontend/assets/data.js  
→ 页面渲染

后续图片增加不直接手改 data.js。
